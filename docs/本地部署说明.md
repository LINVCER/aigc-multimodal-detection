## 三、一键启动脚本

在 `E:\dev-tools\` 下已生成三个脚本，双击即可：

```
start-redis.bat      启动 Redis（6379）
start-backend.bat    启动 Java 后端（8080）
start-inference.bat  启动 Python 推理（8000）
start-frontend.bat   启动 Web 前端（5173）
```

**启动顺序**：Redis → 推理 → 后端 → 前端。后端启动大约要 15 秒，看到
`Tomcat started on port 8080` 就算成功了。
四个服务互相独立，任一挂掉不影响其它端启动（推理没起时后端 health 会返回 3004）。

## 四、手动启动命令（脚本内容对照）

### 1. 后端

```bat
set JAVA_HOME=E:\dev-tools\jdk-21.0.2
set MYSQL_PASSWORD=123456
cd /d "<项目根目录>\backend-java\standalone-app"
"%JAVA_HOME%\bin\java.exe" -Dfile.encoding=UTF-8 -jar target\standalone-app-0.1.0-SNAPSHOT.jar --server.port=8080
```

> `--server.port=8080` 必须加。系统环境变量里有 `SERVER__PORT=11433`，
> 会覆盖配置文件里的 8080，而 11433 已被别的程序占用。

### 2. 前端

```bat
cd /d "<项目根目录>\web"
npm run dev -- --host 127.0.0.1
```

> `--host 127.0.0.1` 建议加。不加的话 vite 只监听 IPv6，用 127.0.0.1 访问会打不开。

### 3. Python 推理服务

```bat
cd /d "...\deploy\inference-python"
E:\dev-tools\venv-inference\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

依赖已装在 `E:\dev-tools\venv-inference`（torch 2.14.1+cpu、transformers 4.57.6、
fastapi 0.115.6、jieba、openai、redis 等）。

> 不设 `TEXT_CHECKPOINT_PATH` 环境变量时，服务会自动降级为 stub 模式并照常启动，
> 不会 down。要跑真实推理，把队长给的 `.pth` 权重路径设进去即可。

### 4. 改了 Java 代码后重新构建

```bat
set JAVA_HOME=E:\dev-tools\jdk-21.0.2
cd /d "...\backend-java\standalone-app"
E:\dev-tools\apache-maven-3.9.16\bin\mvn.cmd -s E:\dev-tools\maven-settings.xml -o -DskipTests clean package
```

`-o` 是离线模式，依赖已在本地仓库里，19 秒就能编完。

## 六、为什么用 standalone-app 而不是若依基座

项目文档（`RUNNING.md`）推荐的是「克隆若依 Vue-Plus 基座 + 软链业务模块」，
但那套要 6 个前置步骤、还要跑 83KB 的 `ry_vue_5.X.sql` 建全套 `sys_*` 表。

作者另外提供了一个 `backend-java/standalone-app`——**不依赖若依基座的独立启动入口**：

- 直接以 `spring-boot-starter-parent 3.3.4` 为父 POM
- 用 `build-helper-maven-plugin` 把 `ruoyi-detect` 的源码编进来
- 只补了两个 stub 类（`org.dromara.common.core.domain.R`、`ServiceException`）
- **只需要 MySQL**，不需要 Redis、不需要若依基座、不需要 `sys_*` 表

所以本次部署走的是 standalone 路径。接口路径、业务逻辑完全一致。

> 若依基座路径作为备选：clone `https://gitee.com/dromara/RuoYi-Vue-Plus.git` 的 5.X 分支，
> 把 `backend-java/business-modules` 下的两个模块挂进 `ruoyi-modules/`（junction 或软链），
> 再在 `ruoyi-modules/pom.xml` 与 `ruoyi-admin/pom.xml` 里补上模块声明。
> 之后 `mvn -pl ruoyi-admin -am spring-boot:run` 即可，但记得先跑若依的全套 SQL。

## 八、部署中踩过的坑（踩过就别再踩）

1. **JDBC 连接参数不能写 `characterEncoding=utf8mb4`**
   MySQL Connector/J 8.3 只接受 Java 编码名，会直接抛
   `UnsupportedEncodingException: utf8mb4`，导致所有查询报 1500「服务器繁忙」。
   已改成 `characterEncoding=UTF-8`（改的是
   `standalone-app/src/main/resources/application.yml`）。

2. **端口被环境变量顶掉**
   系统里有 `SERVER__PORT=11433`，Spring Boot 的宽松绑定会把它当成
   `server.port`。必须用命令行参数 `--server.port=8080` 覆盖（命令行优先级最高）。

3. **vite 只监听 IPv6**
   默认监听到 `[::1]:5173`，`127.0.0.1:5173` 打不开。加 `--host 127.0.0.1`。

4. **npm install 报 esbuild EBUSY**
   Windows 杀软锁文件的典型表现，直接重跑一次就好。

5. **国内网络**
   GitHub 直连不通（要用 `ghfast.top` 之类的镜像）；
   npm 用 `--registry=https://registry.npmmirror.com`；
   Maven 用阿里云镜像；pip 用腾讯源 `https://mirrors.cloud.tencent.com/pypi/simple/`
   （清华源在本次环境下报找不到包，腾讯源正常）。

## 九、注意事项

- **模型权重缺失**：`models/` 目录被 `.gitignore` 排除了，仓库里没有任何
  `.pth` / `.bin` 权重文件。所以 Python 推理端只能跑 stub 模式，返回的是
  基于文本哈希的**模拟概率**，不是真实检测结果。要真实推理得找队长要模型权重。
- **助手功能**：`assistant/` 需要 OpenAI 兼容的大模型 API Key（配在 `.env`），
  没配的话对话助手不可用。
- 项目里的 `deploy/docker-compose.yml` 引用了 `./doc/sql/init.sql`（路径是错的，
  实际文件在 `docs/sql/`），而且该文件是废弃稿 —— 用 Docker 起的话记得改路径 + 换 schema。
