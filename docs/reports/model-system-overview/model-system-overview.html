01项目概览

面向教育与内容行业的「论文 AIGC 检测平台」，用户提交论文 / 音频 / 图像，系统对内容逐段（或逐区域） 输出 AI 生成概率，经置信度校准后给红黄绿三色标注与整体 AI 率，并生成可下载的 PDF 报告。 文本检测为核心主线，音频与图像作为二、三条增长曲线并行推进。

02系统架构

「基座 + 业务模块」的若依架构：ruoyi-detect 通过 Spring Boot AutoConfiguration SPI 挂载到 RuoYi-Vue-Plus 基座；业务侧只依赖 IInferenceClient 抽象，走 HttpInferenceClient 打 Python 推理，模型与业务解耦，gRPC 就绪后仅换 @Primary bean。

分层原则

Controller 只做参数校验与 R 包裹；Service 加事务与业务规则；Repository 仅仓储抽象； 推理侧的 IInferenceClient 全部返回 Map<String,Object>， 用「跨语言约定 key」在 Python schema 未稳定期保持前向兼容。

04文本模型体系

4.1 当前生产：RoBERTa 老基线

实际在推理层挂载的是 hfl/chinese-roberta-wwm-ext（102M，2019）， 搭配 Focal / R-Drop / EMA / FGM 全套微调技巧，加上四路加权融合（统计特征 15% + RoBERTa 30% + MiMo 30% + DeepSeek 25%）。 训练技巧已饱和 —— 单靠调参很难再往上抠精度，主要 leverage 点已经在 backbone 升级。

07校准与融合

每个检测器独立拟合 Temperature Scaling（L-BFGS 最小化 NLL）+ Platt Scaling（逻辑回归），以 ECE 评估校准质量； 参数于验证集拟合后写入 checkpoint，推理时修正置信度。 这是把「原始概率」转化为可靠「红 / 黄 / 绿」阈值判定的关键环节。

文本融合权重

四路加权 · 长文档 stride=200 分块
路基础权重短文本调整长文本调整
统计特征15%↑-
RoBERTa v3_thesis30%-↑
MiMo30%--
DeepSeek25%--

防御预处理含同形字标准化与零宽字符剥离； 图像侧走四路投票 + 分歧自适应降权。段级 < 0.4 判绿、[0.4, 0.7) 判黄、≥ 0.7 判红， 整体 AI 率取加权平均后按场景阈值（Caffeine 缓存 · 详见 §10）判过 / 不过。

  • 迁移走 Flyway 命名约定：V0.2.0.001 → V0.2.0.003 三个版本，含幂等 ALTER（INFORMATION_SCHEMA 存在性判定）
