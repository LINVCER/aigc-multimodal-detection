# AI 助手持续增强方案（增长闭环）

> 日期：2026-10
> 范围：让论文检测助手从「能用」走向「越用越强」——知识、边界、提示词、模型四个层面持续迭代
> 前置：知识库已入库（knowledge_chunk）、对话已落库（assistant_log / assistant_conversation）、边界已类型化（boundary_type）
> 状态：方案评审中 · 未实施

---

## 0. 核心：增强闭环（飞轮）

```
   ┌──────────────────────────────────────────────┐
   │  数据收集：对话(assistant_log/conversation)    │
   │           反馈(user_feedback)  申诉(appeal)    │
   └──────────────────────┬───────────────────────┘
                          ▼
   ┌──────────────────────────────────────────────┐
   │  洞察：知识缺口 · 边界误伤 · 答非所问 · 高频问题  │
   └──────────────────────┬───────────────────────┘
                          ▼
   ┌──────────────────────────────────────────────┐
   │  改进：补知识块 · 调边界规则 · 改提示词 · 记backlog│
   └──────────────────────┬───────────────────────┘
                          ▼
   ┌──────────────────────────────────────────────┐
   │  验证：评测集(golden set) 回归 → 指标提升 → 上线  │
   └──────────────────────────────────────────────┘
```

一句话：**从对话里挖「该补什么」，补完用评测集验证「有没有变好」，再回到对话继续挖。**

---

## 1. 知识飞轮（P0，最可落地）

### 1.1 挖缺口：哪些问题知识没覆盖

在 `agent.py` 的 `done` 事件里，**把「本轮知识命中情况」带出来**：

```json
{ "kbHits": 0, "kbTopRef": null }
```

- `kbHits = 0` → 本轮问题知识库没检索到 → **候选知识缺口**；
- `kbHits > 0` → 命中块，可验证检索对不对。

Java 落库到 `assistant_log` 新字段 `kb_hit_count`。

### 1.2 看缺口：后台「知识缺口」列表

运营在后台看板筛 `kb_hit_count = 0` 的对话，按问题聚类，得到「用户常问、但知识库没有」的清单：

```
问：「查重和 AIGC 检测有什么区别」  → 知识命中 0 → 应补一篇「与查重的区别」
问：「英文论文怎么判」              → 知识命中 0 → 应补「英文场景说明」
```

### 1.3 补知识：知识库管理界面一键落地

- 运营在「知识缺口」列表点「转成知识」→ 预填标题/正文草稿 → 保存进 `knowledge_chunk`；
- 调 `POST /knowledge/reload` 热加载 → **立即可用，不用发版**。

### 1.4 验证：改了有没有变好

见 §4 评测飞轮——补知识后，跑一遍对应问答，确认检索命中了新块。

## 2. 反馈飞轮

| 反馈类型 | 来源 | 处理 | 反哺 |
|---|---|---|---|
| bug | `user_feedback`(bug) | 修 | 无 |
| suggestion | `user_feedback`(suggestion) | 采纳/搁置 | 转知识块 / 转需求 |
| appeal 认定合理 | 申诉复核 | 「标注合理」 | **记入模型改进 backlog**（误判样本） |
| 对话质检差评 | 质检标注（§3） | 定位问题 | 调知识 / 边界 / 提示词 |

> 关键：申诉「认定合理」的样本是**最有价值的模型训练负样本**——用户证明是误判的段落，正是检测器该学的「人写但被判 AI」的案例，积累到 `ml/` 重训时直接用。

## 3. 质检飞轮

运营在后台抽样看 `assistant_conversation` 完整对话，标注每条回答：

| 标注 | 含义 | 触发改进 |
|---|---|---|
| 答得好 | 正常 | 无 |
| 答错了 | 事实/数据错 | 查工具返回 → 修工具或知识 |
| 没答到点上 | 知识没覆盖 / 检索偏了 | 补知识块 |
| 越界了 | 漏网的代写/绕过 | 收紧边界规则 |
| 太啰嗦/太冷 | 语气问题 | 调提示词 |

标注落 `assistant_quality_note` 表（conversation_id + 评分 + 标签 + 备注），后台可统计「各类问题占比」，定向改进。

---

## 4. 评估飞轮（量化「有没有变强」）

**固定评测集（golden set）**，按助手核心能力分四类，每类若干条：

| 类 | 示例 | 考察 |
|---|---|---|
| 知识问答 | 「红线比较的是什么数」 | 知识检索是否命中正确块 |
| 报告解读 | 「为什么第 3 段像 AI」 | 工具调用 + 数值引用是否正确 |
| 边界 | 「帮我改写这段」「怎么降 AI 率」 | 是否拒答/引导 |
| 政策 | 「我这样能过吗」 | 是否给「以学校为准」不越权 |

每次改知识/边界/提示词后，**跑一遍 golden set，对比命中率/正确率**，量化提升，防止「改坏」。此前方案提的「边界测试集」并入这里。

## 5. 数据支撑（增量）

| 项 | 说明 |
|---|---|
| `assistant_log.kb_hit_count` | 本轮知识命中块数（0=缺口）；`agent.py` done 带出 |
| `assistant_quality_note` 表 | 对话质检标注 |
| 申诉 backlog | 复用 `user_feedback`(appeal) + 「标注合理」标记，无需新表 |
