# 助手边界与知识结构优化方案

> 日期：2026-10
> 范围：论文检测助手（`deploy/inference-python/assistant/`）的 agent 边界加强 + 知识库分点重构
> 状态：方案评审中 · 未实施

---

## 0. 结论先行

- **边界**：现有 4 层机制里，越界是「事后打标记」而非「事前拦截」，且边界类型只有「改写」一种。建议建立**类型化边界 + 三级响应（硬拦截 / 软标记 / 引导）**，并把「绕过检测 / 代写」这类高危意图在调 LLM 前就拦下。
- **知识**：7 篇内容散文化、术语与平台字段未对齐。建议**块内分点化**（不是切更多块），每块「一句话结论 + 3~5 要点 + 平台对应字段」，并新增一篇「改写边界」与 agent 边界联动。
- **结构**：知识域按平台的「用户旅程」重排（检测前 → 原理 → 读报告 → 核验申诉 → 答辩规范），而不是按主题随意堆。

---

## 1. Agent 边界现状诊断

现有 4 层（都已实现）：

| 层 | 位置 | 作用 | 缺口 |
|---|---|---|---|
| prompt 规则 | [prompts.py:25-29](deploy/inference-python/assistant/prompts.py#L25-L29) | 明确「不代写不改写」 | 全靠模型自觉，可被诱导突破 |
| 意图分类 | [agent.py:26-41](deploy/inference-python/assistant/agent.py#L26-L41) | 7 类 intent 打标 | 只打标不路由，rewrite_request 不触发专门处理 |
| 越界标记 | [agent.py:25](deploy/inference-python/assistant/agent.py#L25) `_REWRITE_MARKERS` | 事后给 done 打 boundary_flag | **流已发出才标记**，且只有「改写」一种类型 |
| 内容安全 | [safety.py](deploy/inference-python/assistant/safety.py) | 入口/出口检查 | 默认 none 放行；msgSecCheck 管不了「学术越界」 |

**核心结论**：学术助手的真实风险不是「色情暴力」（msgSecCheck 管的那类），而是**学术不端诱导**（代写、教绕过检测、编申诉理由、越权承诺），这类只能靠「意图 + 规则 + 边界知识」自己管，而现状恰恰是最薄的一环。

## 2. 边界加强方案

### 2.1 边界类型化（从「改写」一种 → 六类）

| 类型 | 触发示例 | 响应 | 现状 |
|---|---|---|---|
| `rewrite` 成品改写 | 「帮我改写这段」「把这段润色一下」 | 软拦截 + 引导 | 仅事后 flag |
| `ghostwrite` 代写 | 「帮我写引言」「整篇帮我写」 | **硬拦截** | 无 |
| `bypass` 绕过检测 | 「怎么降 AI 率」「怎么洗稿不被查」 | **硬拦截** | 无 |
| `appeal_fabricate` 编申诉理由 | 「帮我编个申诉理由」 | **硬拦截** | 无（只确认理由，不验真假） |
| `overpromise` 越权承诺 | 「我这样能保证过吗」 | 软引导（不给承诺） | prompt 有，非结构化 |
| `off_topic` 无关领域 | 医疗/法律/情感危机 | 软引导带回 | 无 |

### 2.2 三级响应（关键：拦在 LLM 之前）

```
用户输入
  → classify_intent() 命中硬边界意图(ghostwrite/bypass/appeal_fabricate)
       → 直接回拒答模板，不进 LLM（省 token、保证不越界）
  → 否则进 LLM 工具循环
       → 输出后扫描 BOUNDARY_RULES
           命中 → done.boundaryFlag = 类型（审计）+ 追加一句「以上仅供参考，不建议直接使用」
```

实现点（改动小、收益大）：

1. `_INTENT_RULES` 增加 `ghostwrite` / `bypass` 意图正则；`classify_intent` 命中即走硬拦截分支。
2. `_REWRITE_MARKERS` 扩展为 `BOUNDARY_RULES: list[(type, regex)]`，多类型命中，`boundary_flag` 从 bool 改 string（或加 `boundary_type`）。
3. 新增 `REFUSALS` 拒答模板字典（按类型），语气对齐「学长学姐」人设，先共情再拒绝。
4. `AssistantLog` 已预留 `boundary_flag` 字段，只需把类型写进现有 `intent` 或新增列。

### 2.3 边界与平台特性对齐（口径）

- **humanize 占位**：平台当前不提供改写能力（[main.py:274](deploy/inference-python/main.py#L274) 明示「状态待定」）→ 助手边界必须说清「我不提供改写/代写」，而非「我不能」（前者是产品事实，后者是推脱）。
- **溯源**：可以说「疑似来源」，不能说「这篇就是 XX 写的」——概率不是定性。
- **阈值**：只说平台默认值 + 「以你学校最新规定为准」，绝不承诺「能过 / 保证达标」。

## 3. 知识内容分点完善

### 3.1 现状问题

7 篇均为散文式长段（每块 200~500 字），三个问题：

1. **信息密度低**：模型引用时要读完整段才找到要点，token 浪费；
2. **术语漂移**：知识里写「AI 率」「概率」，报告字段是 `aiRate`/`calibratedProb`/「整体 AI 率」——对不上，模型容易答非所问；
3. **不可扫读**：运营改内容时，无法快速定位某一条要改的知识。

### 3.2 分点规范（模板）

```markdown
## 块标题（一句话可搜）

**结论**：用一句话说清本块要回答的问题。

- 要点 1：…
- 要点 2：…
- 要点 3：…（3~5 条，每条一句话）

**平台对应**：报告里的「整体 AI 率」/「红线阈值」/「置信区间」字段；工具 explain_paragraph / get_threshold_policy。
```

**改前 vs 改后示例**（03-policy-thresholds 的「红线比较的是什么数」）：

> **改前**（散文）：
> 「比较的是整篇论文校准后的整体 AI 率，不是某一段的概率，也不是红段的数量。整体 AI 率是正文段落按字数加权的平均。参考文献、致谢、目录、标题等非正文内容不参与计算。」

> **改后**（分点）：
> ```
> ## 红线比较的是什么数
> **结论**：红线比的是「整篇校准后的整体 AI 率」，不是某一段、也不是红段数量。
> - 整体 AI 率 = 正文段落按字数加权的平均
> - 参考文献 / 致谢 / 目录 / 标题等非正文，不参与计算
> - 某一段红不代表整篇超标，看整体
> **平台对应**：报告顶部「整体 AI 率」字段；工具 get_task_detail 返回 aiRate + threshold
> ```

### 3.3 关键约束：分点 ≠ 切更多块

- 切块单元仍是 `##`（BM25 + 倒排索引按块召回），**块内分点**；
- 不要把每个要点切成独立 `##`——会导致检索召回碎片化、`knowledgeChunks` 暴涨、语义被拆散；
- 每篇保持 5~7 块不变，只把每块的正文从散文改成「结论 + 要点 + 平台对应」。

## 4. 按平台特性构建知识域结构

### 4.1 平台概念模型 → 知识域映射

平台真实特性（报告字段 / 6 场景红线 / 红黄绿 / 溯源 / 7 工具 / 申诉核验）对应用户旅程 5 阶段：

| 用户旅程 | 平台特性 | 知识域（篇） |
|---|---|---|
| 检测前（上传） | 6 场景 · 红线 20/15/10/15/30/25 | 03 政策红线 |
| 检测原理 | 段落切分 · 校准 · 置信区间 · 溯源 · 红黄绿 | 01 检测原理 |
| 读报告 | aiRate · threshold · sourceLabels · 段落 | 02 误判（为什么像 AI） |
| 核验 / 申诉 | 置信区间跨线 · 过程材料 · 申诉队列 | 06 申诉 + 07 核验 |
| 答辩 / 规范 | 报告当材料 · 学术诚信边界 | 04 答辩 + 05 规范 |

### 4.2 现有 7 篇的优化动作 + 新增 1 篇

| 篇 | 优化 | 新增「平台对应」 |
|---|---|---|
| 01 检测原理 | 分点化 | 段落级 / 句级字段、红黄绿阈值 0.4/0.7 |
| 02 误判 | 分点化，误判特征列清单 | 溯源标签、置信区间跨线 |
| 03 红线 | 6 场景红线表格化 | 场景枚举、阈值字段 |
| 04 答辩 | 材料清单分点 | 报告 PDF、模型版本字段 |
| 05 规范 | 合理使用边界分点 | 与 01 检测原理、06 申诉联动 |
| 06 申诉 | 流程步骤分点 | create_appeal 工具、反馈状态 |
| 07 核验 | 自查三步分点 | 置信区间、表层特征 |
| **08 改写边界（新增）** | **为什么平台不提供代写/改写 + 你能得到什么帮助** | humanize 状态待定、agent 边界联动 |

> 08 的定位：把 agent 的边界规则「翻译」成一篇用户可读的知识，模型在被问「帮我改」时能引用它讲清为什么，而不是只说「我不能」——这是**边界与知识的联动**，是本次方案里价值最高的一块。
