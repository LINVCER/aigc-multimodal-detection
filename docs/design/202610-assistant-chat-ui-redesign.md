# 助手对话界面重构方案

> 日期：2026-10
> 范围：web `AssistantDrawer.vue` / uniapp `pages/assistant/chat.vue` 的对话界面结构与样式
> 状态：方案评审中 · 未实施

---

## 0. 现状诊断（按严重度排序）

| # | 问题 | 现状 | 影响 |
|---|---|---|---|
| 1 | **Markdown 不渲染** | 模型输出 `**加粗**`、`- 列表`，前端用 `white-space: pre-wrap` 纯文本展示 | 用户看到 `**加粗**` 字面量，可读性差 |
| 2 | **头部信息过载** | 头像+名称+报告标题+「历史/新对话/关闭」+报告下拉+段落快捷条全挤在顶部 | 视觉层次混乱，找不到重点 |
| 3 | **报告上下文无标识** | 绑定报告只在头部小字显示，对话流里看不到「正在聊哪份报告」 | 切报告后用户易迷失 |
| 4 | **工具调用太简陋** | `text chips`，无图标、无状态动效 | 「正在分析第 3 段」和「已找到 3 条资料」观感一样 |
| 5 | **缺复制/反馈** | 助手回答无法一键复制；无点赞/点踩 | 用户要手动选字复制，体验割裂 |

---

## 1. 调研结论

**外部参考**：

- **GPTZero**（[Advanced Scan Highlighting](https://gptzero.me/news/advanced-scan-even-more-accurate/) · [Compare with AI Text](https://gptzero.me/news/inside-our-new-compare-with-ai-text-tool/)）：核心竞争力是**句子级高亮 + 逐句解释**，把「为什么判 AI」可视化，而不是给一个分数。
- **Pangram AI Detector**（NY Product Design Awards 获奖）：检测类产品同样靠「报告可视化 + 来源溯源」做信任感。
- **主流 AI 助手通用模式**（ChatGPT / Claude / Perplexity）：① Markdown 渲染是底线；② 工具调用可视化（「正在搜索…」）；③ 回答可复制 + 点赞点踩；④ 对话绑定的「上下文/来源」有明确标识。

**对我们的启示**：本产品的差异化是「段落级解释 + 溯源」，所以对话界面**不能是纯聊天**，应该把「报告数据」和「聊天」融合——这是竞品没做、而我们正在做的方向。

## 2. 页面结构设计

### 2.1 现状 vs 优化后（wireframe）

```
【现状】                        【优化后】
┌─────────────────────┐        ┌──────────────────────────┐
│ AI  论文检测助手 报告标题│        │ AI  论文检测助手     [历史][新][×]│
│ [报告下拉] [新][关闭]    │        ├──────────────────────────┤
├─────────────────────┤        │ 报告选择下拉（一行）          │
│ [整体][段3 87%][段5]  │        ├──────────────────────────┤
├─────────────────────┤        │ 📄 上下文卡（绑定报告时）      │
│ 欢迎语               │        │  《报告标题》 AI 26% / 红线15%│
│ [快捷问题chips]       │        │  [整体怎么看][段3·87%][段5·72%]│
│ 气泡（纯文本，**加粗**） │        ├──────────────────────────┤
├─────────────────────┤        │ 消息流（Markdown 渲染）       │
│ 免责 + 输入 + 发送     │        │  气泡 + 工具调用图标 + 复制    │
└─────────────────────┘        ├──────────────────────────┤
                               │ 输入区（复制已并入消息内）      │
                               └──────────────────────────┘
```

### 2.2 分层（4 区，职责单一）

| 区 | 职责 | 内容 |
|---|---|---|
| **头部** | 身份 + 全局操作 | 头像/名称 + 「历史·新对话·关闭」，**报告标题从头部移除** |
| **报告选择** | 换上下文 | 一个紧凑下拉（通用咨询 / 最近 DONE 报告） |
| **上下文卡** | 当前报告的「身份」 | 绑定报告时显示：标题 + AI 率 + 红线 + 达标状态徽章 + 段落快捷 chips |
| **消息流** | 对话主体 | Markdown 渲染气泡 + 工具调用图标 + 复制按钮 |

> 关键改动：把「报告信息」从头部小字**降级为一张上下文卡**，让「正在聊哪份报告」一目了然；头部只留身份和操作。

## 3. 样式升级点

### 3.1 Markdown 渲染（P0，收益最大）

- **不自研解析器、不引重型库**：写一个 ~40 行极简渲染器，白名单支持：
  - `**加粗**` → `<strong>`
  - `- ` / `1. ` 列表 → `<ul>/<ol>`
  - `` `code` `` → `<code>`
  - 换行 → `<br>`，空行 → `<p>`
- **安全**：先 HTML 转义全文，再做白名单标签替换（`v-html` 前转义，杜绝 XSS）。
- 输出前统一把回答里的列表项间距、加粗做好，读起来像「结构化说明」而非「一坨」。

### 3.2 工具调用可视化

把 `tool_call` 从文字 chip 升级为「图标 + 状态」：

| 工具 | 图标 | 进行中 | 完成 |
|---|---|---|---|
| get_task_detail | 📊 | spinner | ✓ |
| explain_paragraph | 🔍 | spinner | ✓ |
| search_knowledge | 📚 | spinner | ✓ |
| detect_text | 🧪 | spinner | ✓ |
| get_threshold_policy | 📏 | spinner | ✓ |
| create_appeal | ✍️ | spinner | ✓ |

状态色沿用 tokens：running=`--system-blue`、done=`--system-green`、failed=`--system-red`。

### 3.3 上下文卡（复用平台数据）

绑定报告时，消息流顶部放一张轻量卡（数据来自 `taskDetail`）：

```
📄 《基于深度学习的…》          [✓ 超标 11.4pp]
   整体 AI 26.4%  ·  红线 15%  ·  正文 42 段
   [整体怎么看] [段 3 · 87%] [段 5 · 72%] [段 8 · 61%]
```

- 达标徽章颜色沿用 `summaryColor` 逻辑（绿/橙/红）；
- 段落 chips 直接点 = `analyzeParagraph`（已有逻辑，只挪位置、不换数据源）。

### 3.4 复制 + 反馈

- 每条 assistant 气泡右下角加「复制」图标按钮（`navigator.clipboard`）；
- （可选，P1）点赞/点踩，落 `user_feedback` 表（category=suggestion 复用）。
