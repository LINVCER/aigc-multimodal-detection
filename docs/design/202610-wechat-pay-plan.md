# 微信扫码支付（Native）+ 额度/计费方案

> 2026-10 · 状态：方案，待前置商务三项（§8）到位后开工联调。
> 关联：`202610-feature-backlog.md` 第 7 项「额度/计费闸门」；部署与备案见功能缺口表 P0。
> 一句话：技术不难，**真正的阻塞是主体资质 + 备案 + 类目审核**。

## 0. 为什么做

- 4 核 8G 推理成本有限，必须有**免费额度闸门**控流量；要变现得能收费。
- 扫码支付（Native）适配我们的 PC Web（Vue）；App 侧后续再接 H5/JSAPI。

## 1. 支付方式选型

| 端 | 方式 | 本期 |
|---|---|---|
| Web PC（Vue） | **Native 扫码支付**（下单拿 code_url → 生成二维码 → 扫码付 → 回调） | ✅ 先做 |
| App（uniapp H5） | H5 支付 | 二期 |
| 小程序 | JSAPI | 小程序搁置，暂不做 |

同时接**支付宝电脑网站支付**作为并行渠道（结构同构，二期）。**不用聚合支付**（虎皮椒/PayJS 等）长期承载：费率高、合规与稳定性风险。

## 2. 前置条件（商务线，必须先办）

1. **主体资质**：个人不能开通。需**个体工商户或公司**营业执照 + 对公账户或法人个人账户。
2. **备案域名**：网站 Native 要 ICP 备案 → 必须**大陆服务器 + 备案域名**（香港免备案但接不了支付）。
3. **类目审核**：如实报「教育/论文检测」类目；「代写/降重」会被拒，我们定位检测+自检。
4. 拿到：**MchID**、认证 appId、APIv3 密钥、商户证书序列号、商户私钥、微信平台证书。

## 3. 技术流程（APIv3）

```
前端选套餐 → 后端创建订单(本地 out_trade_no) → 调 Native 下单 API 拿 code_url
   → 后端生成二维码返前端 → 用户微信扫码支付
   → 微信异步回调 /api/v1/pay/notify(加密) → 解密+验签 → 订单置已支付 → 发额度
   → 前端轮询订单状态 / 查单接口兜底 → 支付成功跳转
```

- **签名**：商户私钥签请求；回调解密 + 用微信平台证书验签。
- **幂等**：同一 `out_trade_no` 回调可能多次，发额度前判「订单未处理」才发，防重复到账。
- **兜底**：回调可能丢，加**主动查单**定时补偿；支持关单、退款。
- **密钥**：APIv3 密钥 / 商户私钥是机密，走配置中心或环境变量，**不进 git**。

## 4. 数据模型

- `pay_order`：id、user_id、out_trade_no、plan_code、amount、status(created/paid/closed/refunded)、transaction_id、paid_at、created_at。
- `user_quota`：user_id、balance（剩余次数或额度）、free_used、updated_at。
- `quota_log`：user_id、delta、reason(free/purchase/consume/refund)、order_id、created_at。

## 5. 额度闸门（和支付绑定）

- 每个用户有**免费额度**（如每月 N 次整篇检测）；即时测一段可更宽或免费。
- 提交检测前校验额度：够则扣减，不够则引导购买。
- 购买套餐 → 支付成功回调 → `user_quota.balance += 套餐额度`，写 `quota_log`。
- 退款 → 回滚额度。

## 6. 接口

| 接口 | 用途 |
|---|---|
| `GET /api/v1/pay/plans` | 套餐列表 |
| `POST /api/v1/pay/order` | 下单，返回 out_trade_no + 二维码（code_url） |
| `GET /api/v1/pay/order/{no}` | 查订单状态（前端轮询） |
| `POST /api/v1/pay/notify` | 微信异步回调（加密，解密验签，幂等） |
| `GET /api/v1/me/quota` | 我的额度 |

## 7. 落地顺序

1. 后端订单 + 额度 + 查单骨架（可先用沙箱/桩回调联调）。
2. 商户号到位 → 填证书 → Native 下单 + 回调真联调。
3. 前端套餐页 + 二维码 + 轮询 + 额度展示（替换个人中心「额度余额」占位）。
4. 二期：支付宝渠道、App H5 支付、发票/对账。
